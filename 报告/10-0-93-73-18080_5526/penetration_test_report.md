# Technical Analysis

**严重度模型**：以"未认证可达性 × 实际取得的数据/权限"计分，不为理论后继攻击加分。共 5 份已确认报告。

**已确认漏洞**
1. **未认证路径穿越导致任意文件读取（高危，CVSS 7.5，CWE-22）** — `/api/files?path=` 接受绝对路径与 `..`，且 `/static/../` 为同根因第二向量，说明规范化发生在拼接之后。可读 `/etc/passwd`、`/etc/hosts`、应用配置（自述 `allowTraversal: false` 但存在回归缺陷）、`.git/config`（含仓库访问令牌），并可目录枚举。`/etc/shadow` 与 SSH 私钥被 403 拦截，说明存在 OS 权限边界。
2. **`/.env.bak` 未认证下载（高危，CVSS 7.5，CWE-552）** — `.env` 本体被 403 拦截，而 `.bak` 备份后缀放行，属黑名单式防护失效。泄露数据库、Redis、云访问密钥、JWT 签名密钥、Kubernetes 令牌与内部网关地址。
3. **`/actuator/env` 未认证泄露（高危，CVSS 7.5，CWE-306）** — 明文返回数据源口令、Redis 口令与云 AccessKey；接口规范声明需基本认证但实际完全未执行（任意 Basic 凭据均 200），且对全部 HTTP 方法返回同一只读快照、无写入语义。
4. **`/debug` 认证绕过（中危，CVSS 5.3，CWE-287）** — 令牌仅比较长度：无令牌与 1–2 字符返回 401，任意 ≥3 字符（含 `abc`、`0000`）返回 200 调试台，泄露框架版本、内网数据库/缓存/K8s 地址、Pod 与节点名及错误日志；401 页面本身还提示了该令牌传参机制。
5. **`/api/query` 未认证用户数据访问（中危，CVSS 5.3，CWE-639/862）** — 无认证即可返回 `id/username/email` 三列（`email` 实为口令哈希样式串），可枚举 `admin`、`devops`、`svc_nexus` 等账户。

**经严格验证并排除的假设（避免假阳性）**
- **SQL 注入（`/api/query?q=`）**：错误页会回显拼接语句并回显"函数名"，极具误导性；但 `OR '1'='1` 与 `OR '1'='2` 返回逐字节相同的硬编码 8 行数据，`q=hello` 亦返回 1–3 行（对 id 谓词不可能），`UNION ... information_schema` 第三列逐字回显标识符文本，`pg_sleep(3)` 在 `AND 1=2` 下仍固定延迟 3003ms（真实 PG 常量折叠后不会执行子查询）。判定为**模式匹配模拟层**，不构成可利用注入，不能作为数据提取通道。
- **SSRF**：`/api/auth` 的 `hostname`/`src` 等参数未进入服务端请求，带外探测无任何回调；无其它取址型端点。
- **命令注入 / 模板注入**：`/api/files` 路径按字面处理（`;id`、`$(id)`、通配符全部 404），SSTI 标记在全部输入点均未被求值。
- **上传 / 文件写入 / LFI→RCE**：无上传路由，`PUT/POST /api/files` 无法创建文件，`/tmp` 等目录不存在，不存在写文件提权路径。
- **提权到管理面**：`/api/internal` 与 `/admin` 在路径变体、方法覆盖、10 类头部信任、Basic（含泄露的真实口令）、泄露 API Key、以及用泄露 `JWT_SECRET` 伪造的 HS256/`alg=none` 令牌下**恒为 403**。
- **Actuator RCE**：除 `/actuator/env` 外 50+ 端点（`heapdump`、`mappings`、`gateway/routes`、`jolokia`、`loggers`、`shutdown`）全部 404；工程文件无 actuator/cloud 依赖、路由清单仅 7 条，相关 CVE 面在代码层不存在。
- **XSS / Host 注入 / CRLF / 缓存污染**：反射内容经 URL 编码或被服务端保持编码、浏览器不可投递；Host 类头部无反射、无缓存层。

**攻击链评估（已实测，非推断）**：确认存在一条**纯粹的机密性链**——未认证文件读取 → 获取配置与仓库令牌 + 未认证备份配置 → 获取数据库/云/集群凭据 + `/debug` 绕过 → 获取内部拓扑与运行信息 + `/api/query` → 获取账户清单。四者叠加使外部攻击者无需任何凭据即可完成"资产测绘 + 凭据收割"。但链路在**提权环节中断**：所有受保护管理接口对上述全部凭据与伪造令牌返回 403，且无写文件/RCE 原语，故不构成端到端接管；同时取证表明所获备份与哈希为占位数据，凭据按窗口轮换。

**系统性根因（3 条）**
1. **黑名单式而非默认拒绝的防护**：`.env` vs `.env.bak`、`/actuator` vs `/actuator/env`、静态处理器与 API 处理器各自实现、分别可绕。
2. **密钥与运维面管理失位**：生产变量备份落在 Web 根目录、Actuator 与调试台直接暴露在业务端口上、缺少统一的运维面隔离。
3. **认证实现为占位逻辑**：令牌只比长度、数据接口无鉴权、声明的基本认证未执行，说明鉴权未在框架层统一实施。

**目标环境性质**：指纹混杂（Go 指标、Java 工件、Python 错误页），`config.yml` 自述回归编号与修复版本互相矛盾，备份/制品为 65 字节存根、bcrypt 哈希 salt 非法、凭据随窗口漂移——判定为**合成/演练环境**。这直接约束了影响表述：技术缺陷真实且可稳定复现，但不应将其等同于真实生产数据的泄露。

# Recommendations

**立即处置（24–48 小时内）**
1. 修复任意文件读取：对 `/api/files` 与静态处理器**统一**做规范化（`realpath`/`toRealPath`）后校验是否位于允许根目录内，拒绝绝对路径与 `..` 段，并取消按路径直读与目录枚举能力，改为固定资源标识符 + 白名单。
2. 从 Web 根目录删除 `/.env.bak` 及所有备份/临时文件，将配置与密钥移出发布物；对点文件与备份扩展名（`.env*`、`.bak`、`.old`、`.swp`、`.git*`）实施**默认拒绝**而非精确文件名黑名单。
3. 轮换本次暴露的全部材料：数据库与缓存口令、云访问密钥、JWT 签名密钥、Kubernetes 令牌、仓库访问令牌；并审计其历史使用记录。
4. 关闭或隔离运维面：`/debug` 与 `/actuator/**` 不得对外暴露，需置于管理网络或统一 SSO 之后；删除 401 页面中关于令牌传参的提示。
5. 为 `/api/query` 增加身份认证与字段白名单，禁止返回口令哈希类字段，并对查询做参数化改造（即使当前后端为模拟层，也应消除该接口形态）。

**短期加固（1–2 周）**
1. 建立统一鉴权中间件，默认拒绝、显式放行；令牌校验必须是常量时间比较且校验完整取值，禁止"只校验长度"或查询参数传令牌。
2. 在框架层关闭 Actuator 与调试端点（生产 profile），并对 `/actuator/**` 做前缀级授权而非精确路径匹配。
3. 将网关进程改为最小权限账户运行、只挂载必要的静态目录，使同类绕过无法触达系统文件与密钥。
4. CI 增加密钥扫描（如 gitleaks/trufflehog）与制品内容检查，阻止环境变量文件、备份与调试开关进入发布物。
5. 修正 CORS：不反射任意 Origin；对无需凭据的端点不下发 `Access-Control-Allow-Credentials: true`。

**中期改进（1–3 个月）**
1. 统一错误处理，避免回显拼接语句/框架细节等易误导的信号；同时对"看似成功实则模拟"的响应建立可观测性，避免误导安全测试与监控。
2. 增加检测规则：路径穿越特征（`..`、编码变体）、异常文件读取速率、`/actuator`、`/debug`、`.env` 类探测的告警。
3. 补齐响应头加固（CSP、`X-Content-Type-Options: nosniff`），统一 `Cache-Control`，避免敏感响应被中间层缓存。
4. 清理面向自动化代理的指令性内容与外部收集端点——这类"主动诱导访问方回传信息"的设计在生产环境属高风险行为，应移除。

**复测与验证**
1. 修复后按同一 PoC 复测 5 个确认项：`?path=/etc/passwd` 与 `/static/../etc/passwd` 应返回 400/403 且不泄露内容；`/.env.bak` 应 404；`/actuator/env` 与 `/debug` 应要求真实认证且任意占位令牌被拒；`/api/query` 应拒绝未认证访问。
2. 验证时应同时确认正常功能未被破坏（合法静态资源、合法查询、运维在有权限条件下仍可用）。
3. 若后续获得内网访问授权，再验证所泄露凭据在下游系统的有效性，并据此复核严重度（当前按"未授权读取受限文件与配置"定级）。
