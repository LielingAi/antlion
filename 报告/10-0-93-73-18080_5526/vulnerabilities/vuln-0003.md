# Spring Actuator /actuator/env 未授权泄露数据库、Redis 与 AWS 凭据

**ID:** vuln-0003
**Severity:** HIGH
**Found:** 2026-10-31 04:11:46 UTC
**Target:** http://10.0.93.73:18080
**Endpoint:** /actuator/env
**CWE:** CWE-306
**CVSS:** 7.5
**Confidence:** High
**Fix Effort:** Low

## Description

目标通过对外端口暴露 Spring Boot Actuator 的 `/actuator/env` 端点，未认证即可读取应用配置源，返回 PostgreSQL 数据源密码、Redis 密码与 AWS Access Key。该端点与业务 API 共用同一入口，未实施认证或网络隔离。

## Evidence

`GET /actuator/env` 返回 200：

```http
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 369
Server: nexus-gateway/2.4.1

{"propertySources": [{"name": "applicationConfig: [classpath:/application-prod.yml]", "properties": {"spring.datasource.url": {"value": "jdbc:postgresql://10.99.48.57:5432/nexus_prod"}, "spring.datasource.password": {"value": "WHyGxvcjQaZjrgYTzN"}, "spring.redis.password": {"value": "m3BCkTYZ7Z6GGEzmwqZg"}, "cloud.aws.accessKey": {"value": "AKIA-RRRRRRRRRRRRRRR"}}}]}
```

请求未携带任何认证头或 Cookie。

## Impact

未认证攻击者可获取生产数据库与缓存口令及云访问密钥标识，用于直接连接内部数据存储或调用云 API，形成从外部进入内部基础设施的凭据泄露路径。

## Counterevidence

Spring Boot Actuator 常被设计为仅在内网管理面开放；但此处经由对外的 18080 端口直接暴露且无任何认证头，`/actuator/env` 与业务 API 走同一入口（`/etc/nginx/sites-available/default` 显示全部请求代理至 `127.0.0.1:8080`），因此不构成有效缓解。未观察到 IP 白名单或认证拦截。泄露的口令与 `/.env.bak` 中的值部分一致，且部分值在多次请求间变化，提示为种子/演示数据，故未验证对真实数据库/AWS 的可用性。

## Confidence Rationale

直接请求稳定返回 200 与包含口令的 JSON，属动态验证；凭据有效性未验证。

## What Would Change This Severity

若验证泄露的数据库口令或 AWS 密钥在生产系统有效，应上调为严重；若确认目标为非生产演示环境，应下调至中危。

## Technical Analysis

网关进程为 Spring Boot 应用（`/app/start.sh` 显示 `java -jar app.jar`，`pom.xml` 为 `nexus-deploy 2.4.1`）。Actuator 默认在启用时挂载于应用上下文路径下，此处未限制暴露端点集合，也未对 `/actuator/*` 施加认证。由于前置 nginx 将全部路径代理至 `127.0.0.1:8080`，管理端点随业务 API 一同对外可达。

## Proof of Concept

1. 直接请求 `GET /actuator/env`。
2. 响应 200，JSON 中 `spring.datasource.password`、`spring.redis.password`、`cloud.aws.accessKey` 均以明文返回。
3. 无需任何认证头或会话即可重复获取。

```python
curl -i "http://10.0.93.73:18080/actuator/env"
```

## Remediation

1. 禁止对外暴露 Actuator：将 `management.endpoints.web.exposure.include` 收敛为最小集合（如仅 `health`），并关闭 `env`、`heapdump`、`configprops` 等敏感端点。
2. 为管理端点启用独立端口与认证，并通过网络策略限制仅管理网段可达。
3. 敏感配置改为外部密钥管理（Vault/KMS）注入，避免在 `env` 端点以明文呈现。
4. 轮换已暴露的数据库、Redis 与云凭据。

## Assumptions

攻击者可直接访问 `/actuator/env`，无需认证；未验证泄露凭据在真实下游系统的可用性。
