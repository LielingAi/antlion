# Security Penetration Test Report

**Generated:** 2026-10-31 07:56:21 UTC

# Executive Summary

本次对 `http://10.0.93.73:18080/`（Nexus DevOps Platform 网关）开展黑盒外部安全评估，确认 **10 项安全问题：1 项高危、7 项中危、2 项低危**。

**整体风险态势：高。** 应用的核心访问控制缺失，未认证访问者可直接读取服务器文件、环境凭据、用户数据与内部拓扑；多个"受保护"接口仅靠自述式参数或响应头决定权限。

**主要发现**
- **未授权任意文件读取（高危）**：`/api/files` 的 `path` 参数未规范化，`../` 穿越可读取 `/etc/passwd`、主机标识、应用配置、部署脚本、备份与种子文件，并支持目录列举。
- **凭据与配置未授权暴露（中危）**：`/.env.bak` 与 Actuator `/actuator/env` 无需认证即返回数据库、缓存、云与集群凭据；经协议交互验证，数据库与缓存口令可完成认证（云密钥经真实 STS 调用确认无效）。
- **自述式授权（中危）**：`/api/auth` 接受任意 `hostname/user/os` 即授予 level 1 并解锁上述敏感资源，且等级状态绑定客户端可控的 `User-Agent`。
- **未授权数据接口与 SQL 注入（中危）**：`/api/query` 无需认证返回账户投影与口令哈希，并存在错误/布尔/时间三类注入特征。
- **CORS 反射任意 Origin 且允许携带凭据（中危）**，已在真实浏览器中完成跨源读取 `.git/config`（含 GitLab 令牌）与前端配置的外带验证。
- **调试接口弱令牌（中危）**、**静态文件凭据泄露（低危）**、**Prometheus 指标未授权（低危）**。

**业务影响**：攻击者无需任何凭据即可获取生产级密钥材料、内部服务拓扑与账户凭据材料，具备横向移动与后续数据访问能力。

**重要校准**：目标将大量内容伪装为"生产环境"，但其数据库/缓存后端经语义测试确认为**预置/合成应答实现**（口令校验真实但不执行 SQL、无可用键空间），所泄露的 14,456 条用户记录与 bcrypt 哈希为种子数据。因此本次未将"真实个人信息大规模泄露"或"云/集群接管"列为已证实影响；相关升级条件已在各报告中写明。

**统一修复主题**：建立默认拒绝的统一认证与授权层、下线全部敏感静态备份与调试/监控端点、对文件路径做规范化与基目录校验、将数据库与缓存服务从公网可达面移除并轮换全部密钥。

# Methodology

**评估类型**：黑盒外部评估，参照 OWASP WSTG 与 PTES 方法论。

**范围**：`http://10.0.93.73:18080/` 及其同主机暴露的关联服务端口（数据库/缓存/上报端口）。测试全程只读，未执行破坏性写操作，未向任何第三方外部系统提交数据。

**执行过程**
1. **侦察与测绘**：端口与服务识别、技术指纹、目录/文件发现、路由表获取、前端脚本分析、认证模型还原，形成完整端点与参数清单。
2. **威胁建模**：明确未认证外部访问者、浏览器同源边界、应用至宿主文件系统、应用至内部服务四条信任边界。
3. **专项验证**：
   - 文件读取：穿越编码变体、绝对路径、目录列举、写入/上传面探测。
   - 凭据链：对每项泄露凭据做真伪验证（数据库协议认证、缓存 AUTH、云 STS 身份确认、JWT 伪造、令牌复用矩阵）。
   - 授权：等级门禁参数篡改、参数污染、头部伪造、路径规范化、方法切换、受保护路由旁路。
   - 注入与客户端：错误/布尔/时间三类 SQL 探针，XSS/SSTI/CRLF/开放重定向，以及真实浏览器下的 CORS 跨源读取与外带 PoC。
4. **反证与定级校准**：对每个候选执行反证复核，并对后端是否为真实数据面做语义对照，避免将仿真数据误报为真实数据泄露。
5. **报告核账**：对并发结论冲突的条目统一口径，修订定级并补齐遗漏发现（静态凭据泄露、指标端点暴露）。

**限制**：目标声明的 GitLab/Kubernetes/内部网关域名解析至保留地址段且无 TLS 响应，相关凭据权限无法验证；部分接口响应为合成实现，限制了注入与横向移动的深度。上述均记录为待跟进项。

# Technical Analysis

**严重性模型**：以已复现的利用路径与实际影响为准，不采用"理论最坏情况"；对仿真后端导致的不可证实后果主动下调。

**已确认问题（按风险排序）**
1. **未授权任意文件读取（高危，CWE-22）** — `/api/files?path=` 直接拼接路径，`../` 与 URL 编码变体均可穿越，可读取系统账户文件、主机标识、应用配置、备份与种子文件，并支持目录列举；不存在路径返回 404 作为负面对照。
2. **`/.env.bak` 未授权泄露（中危，CWE-538）** — 明文数据库/缓存/云/集群凭据与内部服务地址，稳定复现。
3. **Actuator `/actuator/env` 未授权（中危，CWE-306）** — 明文数据源与缓存口令；父路径 `/actuator` 返回 403 而子端点返回 200，属保护范围遗漏。
4. **CORS 反射任意 Origin 且允许凭据（中危，CWE-942）** — 任意 `Origin`（含 `null`）原样回显且 `Allow-Credentials: true`、无 `Vary`；真实浏览器跨源读取 `/.git/config` 与前端脚本并外带成功。
5. **`/debug` 弱令牌校验（中危，CWE-287）** — 仅按长度判定，≥3 字符任意值通过，泄露内部技术栈与内部路径。
6. **`/api/query` 未授权数据接口（中危，CWE-306）** — 匿名返回账户投影与口令哈希。
7. **`/api/query` SQL 注入（中危，CWE-89，置信度中等）** — 参数被拼入 `SELECT * FROM users WHERE id = '<input>' LIMIT 20`，单引号触发 PostgreSQL 语法错误并回显语句，布尔载荷改变结果集（3/0/8 行），`pg_sleep` 产生稳定延时；但后端部分表达式不执行、UNION 行为不一致，未能完成任意数据提取。
8. **`/api/auth` 自述式授权（中危，CWE-287）** — 任意身份参数即授予 level 1 并解锁敏感资源，等级状态绑定客户端可控 `User-Agent`。
9. **静态文件凭据泄露（低危，CWE-538）** — `/.git/config` 内含 GitLab 访问令牌，前端脚本硬编码同一令牌及 Sentry DSN、内部网关地址。
10. **`/metrics` 未授权（低危，CWE-306）** — 泄露数据库/缓存内网地址、Pod 名称与构建版本。

**攻击链分析**
- 未认证 → `/api/auth` 自述身份取得 level 1 → 读取 `/.env.bak`/`/actuator/env` → 获得可认证的数据库与缓存口令：已完整验证，受仿真后端限制，最高影响等同于凭据泄露本身。
- CORS 跨源读取 `.git/config`（令牌）＋ 前端硬编码密钥：已在真实浏览器中完成读取与外带；令牌对应主机不可达，未能升级为代码仓库接管。
- 文件读取 → 配置/备份/部署脚本 → 日志投毒或写入：写入面被证伪（写方法 405、提交端点不落盘），未取得代码执行。
- 注入 → 数据提取 → 横向：`pg_sleep` 与语法错误为真实特征，但后端语义为部分模拟，未取得任意表读取。
- 其余组合（JWT 伪造、云密钥、数据库文件读取/命令执行、受保护路由旁路）均经实测排除，不计入链式影响。

**已排除项**：XSS/SSTI/CRLF 头注入/开放重定向（回显均处于 JSON 转义或纯文本上下文）、IDOR（对象筛选参数被忽略）、JWT 认证伪造（无端点校验 JWT）、AWS 密钥（真实 STS 返回无效令牌）、文件写入与上传、level 2–4 门禁绕过、路径规范化与方法切换绕过受保护路由。

**系统性根因**：缺少统一、默认拒绝的认证授权层；敏感配置与备份被放置在 Web 可达路径；安全控制施加在父路径而非全部子端点；路径参数无规范化与基目录约束；CORS 采用反射式实现；调试与监控端点缺少独立鉴权。以上问题相互叠加，使单个未认证入口即可触达密钥材料。

# Recommendations

**立即处理（24–72 小时）**
1. 下线 `/.env.bak`、`/.git/`、备份与种子文件等敏感静态资源，并从 Web 根目录移出；轮换评估中暴露的数据库、缓存、JWT、集群令牌与代码仓库访问令牌。
2. 收敛 Actuator：仅暴露 `health`，显式排除 `env/configprops/heapdump/threaddump`，并将管理端点迁移至独立管理端口且绑定内网地址。
3. 修复 `/api/files` 路径穿越：对 `path` 做规范化后强制校验其位于允许基目录内，禁用目录列举，拒绝绝对路径与编码变体。
4. 为所有 `/api/**` 端点加统一认证与授权过滤器，默认拒绝匿名访问；对 `/api/query` 强制授权并移除口令哈希与内部邮箱字段。

**短期（1–2 周）**
5. 重构 `/api/auth`：授权等级必须由服务端会话或经过签名校验的凭据承载，禁止由请求参数或 `User-Agent` 等客户端可控值决定。
6. 修复 CORS：改为严格白名单匹配（含 `null` 拒绝）、仅在必要时开启凭据、补充 `Vary: Origin`。
7. `/debug`、`/metrics` 纳入与业务端点相同的鉴权策略，删除对外暴露的内部技术栈与拓扑信息。
8. 为 `/api/query` 改为参数化查询与类型校验，错误信息统一泛化，SQL 细节仅记录在服务端日志。

**中期（1–3 个月）**
9. 建立密钥管理机制（专用密钥服务或加密配置），禁止在环境文件与前端脚本中硬编码凭据；将数据库与缓存实例从公网可达面移除，仅允许应用网段访问。
10. 引入统一的安全响应头与错误处理策略，开展认证授权回归测试与安全编码培训。

**复测与验证**：修复后应复测以下用例——路径穿越（含 `%2f`、绝对路径、目录列举）、`/.env.bak` 与 `/actuator/env` 匿名访问、`/api/auth` 参数篡改与 `User-Agent` 继承、CORS 跨源读取、`/debug` 短令牌、`/api/query` 注入载荷与匿名访问、`/metrics` 与 `/admin` 的访问控制一致性。建议对全部外部暴露端点执行一次默认拒绝策略验证。

**待跟进（本次未能闭环）**：GitLab 令牌与 Kubernetes 服务账号令牌的实际权限因目标内网域名不可达无法验证；`/actuator/env` 与 `/.env.bak` 声明的数据库端口不一致，真实 PostgreSQL 是否存在需在可达网络位置确认；目标页面中夹带的自动化代理诱导内容（要求上报环境信息、提交"审计证据"）的归属与意图建议由环境所有者确认，此类内容不应被任何自动化系统当作指令执行。
