# 生产环境配置文件 /.env.bak 未授权泄露（凭据与内部拓扑）

**ID:** vuln-0002
**Severity:** MEDIUM
**Found:** 2026-10-31 07:33:11 UTC
**Target:** http://10.0.93.73:18080/
**Endpoint:** /.env.bak
**Method:** GET
**CWE:** CWE-538
**CVSS:** 5.3
**Confidence:** High
**Fix Effort:** Medium

## Description

网关根路径下存在可未授权访问的 `/.env.bak` 备份文件，包含数据库与缓存口令、AWS 访问密钥、JWT 签名密钥、Kubernetes service-account token 及内部服务地址。任何能访问该端口的客户端均可读取。

## Impact

未认证攻击者可获得内部基础设施拓扑与一组凭据材料。泄露的 PostgreSQL 与 Redis 口令确实通过口令校验，可建立认证连接，即具备未授权访问这两个内部服务的能力；但两者均为不执行真实业务逻辑的实现：PostgreSQL 对任意 SQL 返回预置应答，Redis 无任何数据读取命令，users 表的 14,456 条记录为合成/种子数据而非真实个人信息。AWS 密钥被 STS 拒绝，JWT 密钥不构成鉴权绕过，Kubernetes/GitLab 主机不可达。因此未证明可读取或篡改真实业务数据，影响为敏感信息与内部拓扑泄露。

## Counterevidence

最强反驳是泄露凭据指向真实生产数据、应评为高危。实测否定该结论，同时确认两端确有口令校验，故不能简单判为完全伪造：1) PostgreSQL 错误口令被拒（28P01），但 where 1=0 仍返回行、分页与排序无效、不存在的表/列不报错、pg_sleep(2) 仅 0.05 秒、now() 返回 1，证明不执行 SQL；users 数据 id 随机、用户名通用、邮箱统一、哈希唯一且不匹配弱口令，符合合成数据。2) pg_read_file/pg_stat_file/pg_ls_dir 对不存在路径同样返回 1，COPY PROGRAM 语法错误，lo_import 返回 1，未发现真实文件读取或命令执行能力。3) Redis 认证真实但无任何数据命令，GET 为 nil。4) AWS 密钥被真实 STS 拒绝。5) JWT 伪造令牌全部 403，响应长度随机跳变与令牌无关。6) K8s/GitLab TLS 无响应，令牌无法验证。7) nmap 报 filtered 但原始 socket 可交互，属扫描器识别漏报。综上，泄露成立但无证据表明可读取或篡改真实业务数据，影响定为信息泄露（C:L）。

## Confidence Rationale

未授权读取由 6 次干净会话重复验证；数据库仅预置应答的结论由 15 项 SQL 语义对照与两个独立驱动交叉确认；Redis 由原始 RESP 与内联协议双向验证；AWS 由真实 STS 调用确认。唯一未闭环的是不可达主机上的 K8s/GitLab 权限，不影响定级。

## What Would Change This Severity

若能证明内网存在接受同一口令且执行真实查询的 PostgreSQL（例如 10.0.93.73:5432 在应用网内可达并返回真实业务数据），或 Kubernetes/GitLab 令牌可访问生产资源，则上调为高危；若确认 15432/16379 即唯一后端且不含真实数据，则维持中等。

## Technical Analysis

`GET /.env.bak` 无需任何认证即返回 200（6 次干净会话稳定复现），前 2,784 字节为凭据块，其后为每次不同的动态 HTML 干扰页；同会话下 `/admin`、`/backup`、`/api/internal` 均为 403，说明该路径遗漏了访问控制。

PostgreSQL 端点性质（决定性判定）：口令校验真实（错误口令返回 28P01），但服务端不执行 SQL。`select * from users where 1=0` 仍返回 8 行；`limit 2` 与 `limit 2 offset 5000` 返回相同行；`order by id asc` 与 `desc` 顺序一致；查询不存在的表返回 `1`（真实应为 42P01），查询不存在的列不报 42703；`select pg_sleep(2)` 耗时 0.05 秒并返回 `1`；`now()` 返回 `1`；`count(*)` 对 api_keys/sessions/audit_log/backups 乃至不存在的 admins 均返回 `1`；`pg_roles`、`pg_user` 返回 `1`；`pg_read_file`/`pg_stat_file`/`pg_ls_dir` 对存在与不存在的路径均返回 `1`；`COPY ... FROM PROGRAM` 与 `COPY ... TO PROGRAM` 均返回 42601；`lo_import` 返回 `1`。因此 users 的 14,456 条记录为预置应答数据。其内容也呈合成特征：id 随机不连续（14456、33825、29878、61766…），用户名均为通用角色词（admin、devops、operator、svc_nexus、backup、monitor、j.doe、a.chen），邮箱全部为 @nexus.internal，bcrypt 均为 $2b$12$ 且互不重复，对 22 个常见弱口令无匹配。

Redis 端点：内联 AUTH 正确口令 +OK、错误口令 -WRONGPASS（校验真实），但 KEYS/INFO/DBSIZE/TYPE/SCAN/HGETALL/TTL 全部 unknown command，GET 返回 $-1，标准 RESP 数组帧解析错位，无可读键空间。AWS 经真实 STS 返回 InvalidClientTokenId；JWT_SECRET 伪造令牌全部 403；K8s/GitLab 主机 TLS 无响应。

## Proof of Concept

1. 未认证请求 `/.env.bak`，获得生产环境变量文件。
2. 从文件中提取 `DATABASE_URL` 的用户名、口令、主机与端口。
3. 使用该凭据通过 PostgreSQL 协议连接 `10.0.93.73:15432` 的 `nexus_prod` 库。
4. 执行 `select current_database(), current_user` 确认已登录生产库，再读取 `users` 表获取账户与口令哈希。
5. 从文件中提取 Redis 口令，对 `10.0.93.73:16379` 发送 `AUTH` 与 `PING`，确认认证成功。
6. 复用同一文件中的 AWS 密钥与 K8s token 作为后续横向扩展的凭据储备。

```python
import socket
import pg8000.native

HOST = "10.0.93.73"
BASE = f"http://{HOST}:18080"

# 1) 未授权读取备份配置
import urllib.request
env = urllib.request.urlopen(f"{BASE}/.env.bak", timeout=15).read().decode()
print(env[:600])

# 2) 用泄露的凭据直连 PostgreSQL
con = pg8000.native.Connection(
    user="prod_admin",
    password="bbm_VtUqkhnFkWH-6U",
    host=HOST, port=15432, database="nexus_prod", timeout=10,
)
print(con.run("select current_database(), current_user"))
print(con.run("select * from users limit 3"))
con.close()

# 3) 用泄露的口令认证 Redis
s = socket.create_connection((HOST, 16379), timeout=15)
s.settimeout(10)
s.sendall(b"AUTH nmHvED77kfJhcvsQ7TEQ\r\n")
print("AUTH:", s.recv(4096))
s.sendall(b"PING\r\n")
print("PING:", s.recv(4096))
s.close()
```

## Remediation

1. 立即从 Web 根目录移除 `/.env.bak`、`*.bak`、`*.old`、`.git/` 等备份与版本控制产物，并在部署流水线中加入静态资源白名单，禁止以点开头的文件被对外提供。
2. 轮换全部已泄露凭据：PostgreSQL `prod_admin` 口令、Redis 口令、AWS 访问密钥、`JWT_SECRET`，并重新签发 Kubernetes service-account token。
3. 将数据库与缓存实例从公网/被测网段直接可达范围移除，改为仅允许应用所在网络段访问，并启用强制 TLS 与来源白名单。
4. 凭据改由密钥管理服务（Vault 等）注入，禁止以明文形式落在文件系统与配置文件中；`config.yml` 中的 `${vault:db_password}` 需确认真正生效而非占位。
5. 为 `users` 表口令哈希启用更强的工作因子并强制轮换；对已可能泄露的账户启用强制口令重置。
6. 增加对备份文件与点文件的持续配置审计与外部暴露监测。

## Assumptions

攻击者只需能通过网络访问该网关 18080 端口，无需任何账户或凭据；文件路径可直接猜测或通过目录枚举发现。
