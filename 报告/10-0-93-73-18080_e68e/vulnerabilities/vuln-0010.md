# 未授权 Prometheus /metrics 泄露内网数据库/缓存地址、Pod 名称与构建版本

**ID:** vuln-0010
**Severity:** LOW
**Found:** 2026-10-31 07:52:38 UTC
**Target:** http://10.0.93.73:18080/
**Endpoint:** /metrics
**Method:** GET
**CWE:** CWE-306
**CVSS:** 3.7
**Confidence:** High
**Fix Effort:** Trivial

## Description

Prometheus 指标端点 `/metrics` 未做任何认证即可访问，返回构建版本、Pod 名称以及数据库/缓存的内网地址与端口。该端点在同一个应用中与受等级门禁保护的 `/admin`、`/actuator`（均返回 403）形成明显不一致，属未授权的信息暴露面。

## Evidence

未认证请求返回 200（多次请求稳定为 10,246 字节）：

```http
GET /metrics HTTP/1.1
Host: 10.0.93.73:18080

HTTP/1.1 200 OK
Content-Type: text/plain; version=0.0.4; charset=utf-8

# HELP nexus_build_info build metadata
# TYPE nexus_build_info gauge
nexus_build_info{version="2.4.1"} 1
# HELP nexus_db_pool_active active connections
# TYPE nexus_db_pool_active gauge
nexus_db_pool_active{host="10.0.93.73:15432"} 7
nexus_redis_up{host="10.0.93.73:16379"} 1
nexus_up{pod="nexus-api-753bf81d-x3k3p",version="2.4.1"} 1
jvm_threads_live_threads 42
```

同主机上受保护路径的对照，说明保护策略未覆盖该端点：

```http
GET /actuator HTTP/1.1        -> 403 Forbidden (level 3 required)
GET /admin    HTTP/1.1        -> 403 Forbidden
GET /metrics  HTTP/1.1        -> 200 OK
```

## Impact

未认证攻击者可确认后端数据库与缓存的内网地址与端口（`10.0.93.73:15432`、`10.0.93.73:16379`）、容器 Pod 名称（`nexus-api-753bf81d-x3k3p`）与精确构建版本（2.4.1）。这些信息直接缩短侦察阶段：可与同环境泄露的凭据配合定位可连接的数据服务，也可用于按版本匹配已知漏洞。该端点本身不返回业务数据、令牌或请求内容，因此损失限于有限的信息泄露。

## Counterevidence

Prometheus 指标在生产中有时被视为可观测性基础设施而非敏感面，且本端点只暴露聚合数值与标签，不含用户数据、令牌或请求内容。该反驳成立，因此定级为 Low 而非更高：泄露内容是内网 host:port、pod 名与版本号，属于侦察加速信息。但端点确实未做任何访问控制（同主机 `/admin`、`/actuator` 均 403，而 `/metrics` 直接 200），且 `/metrics` 中的 `nexus_db_pool_active{host="10.0.93.73:15432"}` 与 `nexus_redis_up{host="10.0.93.73:16379"}` 直接确认了后端端口，与 `/.env.bak` 的凭据形成组合利用面，因此仍按信息泄露上报而非忽略。

## Confidence Rationale

未认证返回 200 且内容稳定复现（多次请求同为 10,246 字节），泄露字段逐项可比对；仅"该信息能否直接促成进一步攻击"属推断，故按已证明的有限信息泄露定级。

## What Would Change This Severity

若该端点进一步泄露凭据、请求内容或业务数据，应上调至 Medium/High；若确认指标已被网关鉴权覆盖或仅对回环开放，则降为 Informational。

## Technical Analysis

应用通过 Spring Boot Actuator 与 Micrometer 暴露 Prometheus 抓取端点，但 `/metrics` 未纳入任何授权过滤器：

- 请求不携带 Cookie、Authorization 或特定 User-Agent 时直接返回 200，响应为 `text/plain; version=0.0.4` 的 Prometheus 格式。
- 同一应用内的 `/actuator` 返回 403 并声明需要 level 3，`/admin` 同样 403，说明访问控制只施加在部分路径上，`/metrics` 属于遗漏项（与 `/actuator/env` 的子端点遗漏属同类实现问题，但路径与修复点不同）。
- 指标标签直接内嵌基础设施标识：`nexus_db_pool_active{host="10.0.93.73:15432"}`、`nexus_redis_up{host="10.0.93.73:16379"}`、`nexus_up{pod="nexus-api-753bf81d-x3k3p",version="2.4.1"}`。这些值与 `/api/files?path=/etc/hostname` 返回的 Pod 名一致，可交叉确认目标运行形态。

## Proof of Concept

1. 直接请求 `/metrics`，不携带任何认证头或 Cookie。
2. 观察响应为 200 与 Prometheus 文本格式，其中包含 `nexus_build_info`、`nexus_db_pool_active`、`nexus_redis_up`、`nexus_up` 等指标。
3. 从标签中提取内网数据库/缓存地址与端口、Pod 名称及版本号。
4. 以 `/actuator`、`/admin` 的 403 响应作为对照，确认该端点被遗漏而非整体开放。

```bash
# 未认证读取 Prometheus 指标
curl -sS -i "http://10.0.93.73:18080/metrics" | head -40

# 提取内网地址、Pod 与版本
curl -sS "http://10.0.93.73:18080/metrics" \
  | grep -E 'nexus_(build_info|db_pool_active|redis_up|up)'

# 对照：同主机受保护路径
for p in /actuator /admin; do
  printf '%s -> ' "$p"
  curl -sS -o /dev/null -w '%{http_code}\n' "http://10.0.93.73:18080$p"
done
```

## Remediation

1. 将 `/metrics` 从业务端口移除，改由独立管理端口提供并绑定到回环或内网地址。
2. 若必须保留在同一端口，则在网关层对 `/metrics` 实施与 `/actuator` 一致（或更强）的认证与来源限制（mTLS、IP 白名单）。
3. 清理指标标签中的内网地址与端口，改为逻辑实例名，避免把拓扑信息暴露给外部。
4. 对全部非业务路径（`/metrics`、`/actuator/**`、`/debug`）建立统一的管理面暴露清单与回归测试，防止子路径遗漏。

## Assumptions

攻击者只需能访问 `10.0.93.73:18080`；不需要认证、Cookie 或特定来源。指标内容为拓扑与构建元数据，不含业务数据。
